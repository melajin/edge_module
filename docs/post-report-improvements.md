# 보고서 이후의 코드 개선

보고서 결과는 당시 구현과 실험 조건의 기록으로 보존한다. 이 문서의 기능은 보고서 작성 이후 추가한 운영 진단과 오류 처리다. 당시부터 존재했지만 설명만 생략한 기능으로 표현하지 않는다.

보고서 해설 `docs/report-detail/`, FG `source_snapshot/`, 기존 평가 기록·fixture·생성 모델 계수는 수정 대상에서 제외한다. 원본 보고서 PDF와 보호 파일의 SHA-256은 로컬 작업 기록에서 대조한다. 판정식이나 모델을 바꾸는 후속 버전의 성능은 이전 보고서 수치로 대신하지 않는다.

## 이번 변경의 범위

- [측정 품질 규칙 1](measurement-quality.md): 수신 순번, 센서 창 품질, 창간 미관측 경계를 분리한다. 구형 로그는 미확인으로 표시한다.
- FG V3 실행 기록: 취득 시도부터 출력 직전까지의 시간, 이전 결과 행의 출력 호출 시간, 현재 런타임 heap 상태를 별도로 관측한다. 센서의 연속 측정이나 실제 전송 완료를 보장하는 값이 아니다.
- [정상 기준 관리](baseline-lifecycle.md): 조건 ID·PPR을 기준과 연결하고, 후보 저장·명시 승인·이전 기준 복원과 저장 실패 보류를 추가한다. 부팅은 측정 대기로 시작한다.
- [101특징 C 계산](../edge_module_c/report_ml/README.md): 작업 공간 초기화 미호출·할당 실패를 신호 오류와 구분한다. 작업 공간 크기와 상태를 조회하고, 정상 특징·모델 계산은 유지한다.

FG V3와 `report_ml`은 별개 실행 경로다. ML 엔진을 FG 펌웨어에 새로 연결하지 않는다. 따라서 FG 실행 기록으로 ML 지연이나 ML 작업 공간 사용을 측정했다고 해석하지 않는다.

## 규칙별 실제 적용 상태

| 규칙 | 현재 저장소에서 확인한 상태 | 이번 처리와 남은 확인 |
|---|---|---|
| 1. 수신·취득·공백 분리 | 취득 메타데이터와 수신 순번·표시가 추가됨 | 기존 동작과 구형 로그 호환을 회귀 검사 |
| 2. 시각과 표본율 구분 | FG 표본은 MCU 읽기 시작 시각. ML 주석에 센서 변환 시각이라는 잘못된 표현이 있었음 | 주석·호출 계약 교정. 센서 내부 변환 시각의 물리적 대응은 실측 필요 |
| 3. 정상 기준과 조건 연결 | FG의 새 기준 상태에 조건 ID·PPR·출처를 저장하고 선택 조건이 다르면 판정 보류 | ID는 사용자가 붙이는 표지. 부착·체결의 대표성은 실측 필요. 구형 저장소는 읽기 전용 보존 |
| 4. 기준 교체 검증 | 336개 연속 유효창 중앙값을 후보로 저장한 뒤 ID를 명시해 승인 | 운영·후보·이전 기준, 복원·재시작·저장 오류 처리를 구현. 실제 전원 중단 시험과 기준 적합성 평가는 별도 |
| 5. 학습·실물 입력 대응 | ML은 도메인 차이 사유와 관측 가능한 차수 mask를 제공 | 자원·입력 계약 설명 교정. 재학습·새 전처리·현장 정확도 평가는 수행하지 않음 |
| 6. 전체 처리 지연 확인 | 취득 공백만으로는 출력 호출의 대기를 알 수 없음 | FG의 취득 포함 출력 전 시간과 이전 출력 호출 시간 추가. 실제 전체 지연은 별도 실측 |
| 7. 동적 메모리 확인 | ML 작업 공간은 heap 할당이며 실패가 신호 오류 사유로 합쳐졌음 | 초기화 상태·크기 조회와 실패 사유 분리. FG의 heap snapshot은 ML 메모리 검사가 아님 |
| 8. 성능 분모 명시 | 보고서 해설은 판정 가능 비율·조건부 탐지·전체 탐지를 이미 구분 | 원래 수치를 보존하고 새로운 결과에도 분모·보류·집계 단위를 표시 |
| 9. 통계 가정과 실측 구분 | 초기 표준편차 정의·정규분포 단정 오류는 저장소 밖 상위 노트에 있음 | 현재 코어의 수식 변경 근거로 사용하지 않음. 아래 해석 원칙 명시 |
| 10. 연속 구간 보존 | 문제의 구형 CSV 예제는 별도 `edge-pdm`에 있음. 저장소 경로는 파일·회차 구분을 사용 | 문제 예제를 반입하거나 현재 코드 결함으로 간주하지 않음 |
| 11. 점수와 확률 구분 | ML은 평균 선형 SVM 마진, 물리 상대 근거는 확률이 아님 | 계약을 명료화하고 기존 계수·정규화·평가 결과 보존 |

## 결과 해석 원칙

표준편차는 데이터의 평균이 아니라 평균 주변의 퍼짐을 나타낸다. 로그 변환은 정규분포를 보장하지 않는다. 정규분포의 단일 값에 대한 ±3σ 이탈 확률을 여러 특징·시간상관·투표가 포함된 시스템의 실제 오경보율로 사용하지 않는다.

평가에는 분자·분모, 보류·무효·제외 입력, 파일·창·독립 운전 회차의 단위를 함께 표시한다. 연속된 여러 창을 같은 수의 독립 실험으로 설명하지 않는다. 보고서의 개발 평가 수치를 새 배포 모델의 실측 정확도로 이전하지 않는다.

ML 결정 마진과 후보 사이 상대 비중은 고장 확률이 아니다. 관측 대역 밖 특징에 계산상 0이나 log floor가 들어가더라도 해당 대역을 측정해 에너지가 0임을 확인한 것은 아니다. 가용 mask와 도메인 차이 사유를 함께 읽는다.

## 검증 경계

호스트 모의시험, 수치 비교, 실제 브라우저 표시, ESP32 빌드는 각각 확인 범위가 다르다. 이번 작업은 장치 업로드·모터 운전·UART 선로 지연·장기 운전·실제 고장 성능 실험을 포함하지 않는다. 소프트웨어 검사에 통과하더라도 실측 전에는 처리 마감 준수, 센서 연속성 또는 고장 탐지 개선을 확정하지 않는다.

기존 보고서의 RAM·Flash 수치는 당시 빌드 기록이다. 새 빌드의 정적 사용량과 런타임 heap·TX 버퍼는 별도 항목으로 보고한다. 할당 실패가 명확히 표시된다는 사실도 메모리 여유가 충분하다는 뜻은 아니다.

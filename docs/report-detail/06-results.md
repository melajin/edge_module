# 6. 평가 결과: 단위·분자·분모와 증거 유형

**보고서 위치:** Ⅳ-1~4(16~19쪽), 표 9~12

CWRU는 분석창 단위, AI-Hub는 파일 단위, B02~B04는 채널별 1.6초 취득 구간 단위로 집계했다. **판정 가능 비율(coverage)**은 유효 판정이 있는 입력의 비율이고, **조건부 탐지율(conditional detection rate)**은 판정 가능한 고장 입력 중 탐지 비율이다. **전체 고장 파일 대비 탐지 비율**은 모든 고장 파일을 분모로 계산한다. 아래 수치는 제출 PDF의 표 9·10 기록이다.

## 시간 이력 투표 정책

보고서 표 10은 4/5 정책과 20-window 정책의 파일 집계를 비교한다.

| 지표 | 기존 4/5 규칙 | 20창 반복 확인 규칙 |
|---|---:|---:|
| 판정 가능한 결함 파일의 탐지율 | $10,218/11,677=87.51\%$ | $9,790/10,806=90.60\%$ |
| 전체 결함 파일 대비 탐지 비율 | $10,218/16,343=62.52\%$ | $9,790/16,343=59.90\%$ |
| 판정 가능한 결함 파일 | 11,677파일 | 10,806파일 |
| 결함 파일 판정 가능 비율 | $11,677/16,343=71.45\%$ | $10,806/16,343\approx66.12\%$ |
| 정상 오경보율 | $538/9,283=5.80\%$ | $884/7,814=11.31\%$ |

20창 규칙은 조건부 탐지율 90.60%, 전체 고장 파일 대비 탐지 비율 59.90%, 판정 가능 파일 10,806개를 기록한다. 4/5 규칙은 각각 87.51%, 62.52%, 11,677개다. 20창 규칙의 판정 가능 고장 파일은 871개, 탐지 파일은 428개 적고, 정상 오경보율은 11.31%다. PDF 표 10은 기존 4/5 정책을 선택했다.

## 4상태 ML 개발 결과와 모델 범위

보고서 ML 절은 Mendeley Mechanical faults 자료의 20개 trial-group을 나눈 5개 fold OOF 평가로 전체 정확도 93.67%, 축 정렬 재현율 86.00%, 기계적 이완 재현율 88.67%를 기록한다. 이 결과는 해당 공개 자료·profile·101특징·모델의 개발 평가값이다.

현재 로컬 export는 다섯 LinearSVC fold의 평균 마진 후보를 제공한다. provenance 필드는 `ensemble_evaluated=false`, `live_validated=false`이며, 네 클래스는 불평형·기계적 이완·축 정렬 불량·정상이다. 실시간 입력 계약은 ADXL345 한 축·512 표본·380~420 Hz·400점 보간·FG RPM으로 구성된다.

## 기록된 소프트웨어·빌드·모델 결과

보고서 19쪽은 Python/C 투표 parity 219건, Python 검사 36건·23개 하위 케이스, C 합성·엄격 컴파일 검사, ESP32 빌드, CWRU 호스트 재생을 기록한다. CWRU 특징·점수 parity는 640창 전체에서 최대 절대차 2.984×10⁻¹³ 및 4.334×10⁻¹³으로 기록됐다. 세부 클래스 정답은 581/640(90.78%)이고, 4/5 투표는 파일별 첫 4창×10파일=40창을 투표 초기 이력으로 사용해 600창에서 집계했다.

ESP32 두 빌드의 링크 결과는 정적 RAM과 플래시 사용량으로 기록돼 있다.

| 빌드 | 정적 RAM | 플래시 | 기록 유형 |
|---|---:|---:|---|
| FG V3 보고서 검증 펌웨어 | 100,380 / 327,680 byte (30.6%) | 320,561 / 1,310,720 byte (24.5%) | FG V3 타깃 펌웨어 링크 결과 |
| CWRU 전체 통합 펌웨어 | 105,308 / 327,680 byte | 375,349 / 1,310,720 byte | CWRU 기능을 포함한 별도 ESP32 통합 빌드 |

두 행은 컴파일·링크 시점의 정적 RAM·플래시 사용량이며 CWRU 저장 파형의 재생은 호스트 기록에 포함된다.

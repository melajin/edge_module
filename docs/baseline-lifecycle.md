# 보고서 이후의 정상 기준 관리

`postreport_v2`는 보고서 이후 추가한 FG 펌웨어의 운영 버전이다. 보고서의 336개 정상 창 중앙값 계산, 1× 진폭·위상 계산과 4/5 판정식은 보존한다. 기준을 운영에 적용하는 절차와 저장 방식은 이 문서의 새 규칙을 따른다. 과거 보고서의 실험 결과가 이 버전을 검증한 것은 아니다.

## 기준을 교체하는 규칙

| 상태 | 의미 | 판정에 사용 |
|---|---|---|
| `current` | 명시적으로 승인한 운영 기준 | 선택한 조건 ID·PPR이 일치하고 저장 보류가 없을 때 |
| `candidate` | 새로 학습하거나 구형 저장소에서 가져온 후보 | 승인 전에는 사용하지 않음 |
| `previous` | 마지막 교체 이전의 운영 기준 | `rollback` 성공 후 사용 |

학습을 다시 시작해도 운영 기준은 보존한다. 336개 연속 유효창의 축별 중앙값을 후보로 저장하고, `approve <후보 ID>`가 성공해야 운영 기준이 바뀐다. 승인 때 기존 운영 기준은 이전 기준으로 이동한다. `rollback`은 운영·이전 기준을 교환하므로 두 번 실행하면 원래 상태로 돌아온다. 후보는 `discard`로 따로 삭제한다.

조건 ID는 영문자·숫자·`_`·`-`로 된 1~12자 문자열이다. 사용자가 부착 위치, 체결, 회전수와 부하 조건을 구분해 붙이는 이름이다. ID 일치만으로 물리적 조건이 같다고 검증되는 것은 아니다. 설치나 운전 조건이 바뀌면 새 ID로 구분하고 실제 조건을 실험 기록에 남긴다. PPR은 1~16 범위이며 실제 FG의 회전당 펄스 수에 맞춰야 한다.

조건 ID 또는 PPR이 운영 기준과 다르면 기준을 삭제하지 않고 판정을 보류한다. 다시 일치시키면 저장해 둔 운영 기준을 사용할 수 있다. 승인과 복원도 선택 조건·PPR이 대상 기준과 일치해야 성공한다.

## 부팅과 명령

부팅은 항상 측정 대기(`paused=true`)로 시작한다. 이 펌웨어는 센서와 FG를 읽으며 팬·릴레이·모터 출력 핀을 제어하지 않는다. `start`와 `stop`은 측정 제어 명령이며 모터 구동·정지 명령이 아니다. 명령은 115200 baud에서 줄바꿈으로 끝낸다.

| 명령 | 동작 |
|---|---|
| `profile` | 선택 조건, 운영·후보·이전 기준, 저장 상태를 출력 |
| `context <ID>` | 사용할 조건 ID를 선택·저장 |
| `ppr <1..16>` | 사용할 FG PPR을 선택·저장 |
| `learn` | 측정을 시작하고 336개 유효창 수집. 기존 후보가 있으면 거부 |
| `approve <후보 ID>` | ID와 조건이 일치하는 후보를 운영 기준으로 승인 |
| `discard` | 후보만 삭제 |
| `rollback` | 조건이 일치하는 이전 기준으로 복원 |
| `import <ID>` | 유효한 구형 기준을 지정한 조건의 후보로 가져옴. PPR도 구형 값을 선택 |
| `start` | 측정 시작. 기준이 준비되지 않으면 고장 판정은 보류 |
| `stop` | 측정을 대기하고 미완료 학습을 중단 |
| `recover` | 저장 보류의 원인을 재확인하고 검증 가능한 상태를 복구. 측정은 대기 유지 |
| `clear` | 새 저장소의 선택 조건·운영·후보·이전 기준을 비움. 구형 저장소는 보존 |

처음 사용할 때는 `profile`의 저장 상태를 먼저 확인한다. NVS API가 namespace·키의 부재를 명시적으로 확인한 경우에만 빈 초기 상태(`not_found`)로 시작한다. 크기 조회·읽기 오류를 “기준 없음”으로 바꾸지 않는다. 저장 보류가 생기면 `recover`로 재확인하며, 데이터가 손상돼 정상 상태를 찾지 못하면 복구를 거부하고 빈 기준으로 덮어쓰지 않는다.

새 기준을 등록할 때의 순서는 `context <ID>` → `ppr <확인한 PPR>` → `learn` → 후보 이벤트 확인 → `approve <실제 후보 ID>`다. 예시의 ID·PPR을 실제 측정 조건 확인 없이 그대로 적용하지 않는다. 구형 기준을 쓰려면 `import <ID>`로 후보를 만든 뒤 그 후보 ID를 승인한다. 가져오기 성공은 새 설치 조건에서의 적합성을 검증한 결과가 아니다.

학습 중 센서·FG·표본 시각 오류, 정지, 조건 변경이나 재부팅이 발생하면 미완료 수집을 폐기한다. 완성해 저장한 후보와 이미 승인한 기준은 유지한다. 상세 프로필 이벤트는 직렬 출력을 오래 점유할 수 있으므로 명령 응답과 후보 완료 시점에 판정의 시간 이력을 초기화한다. 학습 중에는 `profile` 조회도 학습을 중단한다. 336창 수집 중에는 명령을 보내지 말고 측정 로그의 `learn_count`를 관찰한다.

## 저장 실패와 이전 버전 호환

새 상태는 `edgev3p2` namespace의 A/B 슬롯에 전체 상태로 저장한다. 버전·크기·CRC·세대 번호와 값을 검사하고, 쓰기 후 읽어 내용이 같은지 확인한 뒤 RAM 상태에 적용한다. 저장 결과가 불확실하면 운영을 보류한다. 재부팅에서도 두 슬롯을 검사하며, 손상 또는 동일 세대의 충돌을 자동으로 무시하지 않는다.

쓰기는 완료됐지만 읽기 재검사만 실패한 경우에는 실행 중의 RAM에 이전 상태를 유지한다. 이후 재부팅에서 새 사본의 CRC와 전체 내용이 정상이라면 최신 상태로 선택될 수 있다. A/B 저장만으로 이전 실행이 성공 응답을 확인했는지까지 증명할 수는 없다. 그래서 재부팅 후에는 항상 대기하며, `profile`에서 실제 선택된 기준을 확인한 뒤 측정을 시작한다.

`recover`는 후보를 자동 승인하는 명령이 아니다. 검증 가능한 상태만 복구하며 복구 후에도 `start` 또는 `learn`을 명시해야 한다. 모든 사본이 손상된 상황의 원래 값을 만들어낼 수는 없다. 복구 실패 시 로그와 기존 flash 백업을 보존하고 원인을 조사한다. NVS 모의 실패 시험은 실제 전원 차단 내구성 시험과 구분한다.

구형 `edgev3/profile`은 읽기 전용으로 남긴다. 새 `clear`도 이를 지우지 않으며 기준 ID를 재사용하지 않는다. 새 펌웨어가 구형 기준을 자동으로 운영에 적용하거나, 새 저장소의 손상을 구형 기준으로 자동 대체하지 않는다. 반대로 구형 펌웨어로 되돌리면 구형 저장소의 과거 기준을 읽을 수 있으므로 새 버전에서 승인한 기준이 이어진다고 가정하지 않는다.

## 로그 계약

측정 행은 선택한 `context_id`와 사용 가능한 운영 기준의 `baseline_id`를 추가한다. 기준이 없거나 조건이 맞지 않으면 `baseline_id=null`이다. 학습 중 저장된 운영 기준 ID가 표시되어도 해당 창에서 판정을 수행했다는 뜻은 아니다. 기존 `learning`, `reason`, 판정 상태를 함께 읽는다. 구형 로그에는 이 식별자가 없으며 미확인으로 표시한다.

명령·부팅·후보 완료는 `event:"profile"`, `v:1`, `firmware:"postreport_v2"`인 별도 JSON 행이다. `command`, `ok`, `reason`과 `profile` 상태를 기록한다. 각 기준에는 ID, 조건 ID, PPR, 축별 진폭, 학습 창 수, 생성 세션·순번과 출처를 보존한다. `learned`의 창 수는 336, `legacy_import`는 0이며 0은 과거 학습이 없었다는 뜻이 아니라 새 버전에서 재학습하지 않았다는 뜻이다.

수집기와 화면은 이벤트를 측정 결과와 구분한다. 정상 이벤트가 두 측정 행 사이에 있어도 측정 순번을 초기화하거나 누락으로 세지 않는다. `ok:true`는 해당 명령의 성공이며 센서·모터 정상 또는 고장 판정의 정확도를 뜻하지 않는다. 저장 보류 역시 고장 종류가 아니라 운영 상태다.

기준 ID·저장 세대는 32비트 정수다. 펌웨어의 시각·순번은 64비트지만 현재 Python 수집기와 브라우저 계약은 JSON 숫자의 정밀도를 맞추기 위해 `2^53-1`까지만 허용한다. 범위를 넘는 기록은 반올림해 사용하지 않고 거절한다.

## 이번 확인 범위

호스트에서는 후보 생성·승인·복원, 335/336창 경계, 저장 실패·손상·재시작, 구형 기준 가져오기, 로그 호환과 표시를 검사한다. ESP32 빌드와 설치 패키지의 해시는 별도로 확인한다. 장치 업로드, 실제 센서 입력, 전원 중단, 장기 운전, 고장 탐지 성능은 아직 검증하지 않는다.

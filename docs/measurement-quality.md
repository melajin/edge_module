# 측정 품질 규칙 1: 수신 상태와 관측 범위를 분리하기

이 문서는 보고서 이후의 운영 기록 확장을 설명한다. 제출 보고서, `report-detail/`의 보고서 해설, FG V3 `source_snapshot/`, 기존 평가 수치는 이 변경의 대상이 아니다. 보고서의 1× 계산, 정상 기준, FG 검사, 100 ms 시간 단절 처리와 4/5 판정 정책을 유지한다.

## 기록의 세 가지 의미

| 항목 | 확인하는 내용 | 확인하지 못하는 내용 |
|---|---|---|
| 수신 순번 | 동일 부팅 세션에서 관측한 JSON 순번의 연결, 빠짐, 중복, 역행 | 센서가 모든 변환값을 읽었는지, 전송 비트가 모두 원본과 같은지 |
| 취득창 품질 | 표본 수, 시간 간격, 창별 표본율, 유한한 값과 입력 범위 | FG 기준과 정상 기준이 준비됐는지, 특정 고장이 존재하는지 |
| 창간 미관측 경계 | 이전 실제 표본의 읽기 시작과 이번 첫 표본의 읽기 시작 사이 간격 | 놓친 센서 변환의 정확한 개수, 공백 안의 정상·고장 상태 |

JSON 구문 검사를 통과하거나 수신 순번이 이어진다는 사실만으로 연속 측정이 확인되지는 않는다. 이 JSON 통신에는 별도의 프레임 CRC가 없으므로 수신 순번 상태를 전송 무결성 인증으로 표시하지 않는다.

## 추가 취득 메타데이터

FG V3의 기존 결과 필드는 유지하고 `acquisition` 객체를 추가한다. 기존 로그에 이 객체가 없으면 새 품질 항목은 **미확인**이다. 없는 값을 `0`, 정상 또는 연속 관측으로 대체하지 않는다.

| 필드 | 의미 |
|---|---|
| `v` | 취득 메타데이터 버전, 현재 1 |
| `session` | 부팅마다 생성하는 16자리 16진수 식별자. 장치 신원 인증용 값이 아니다. |
| `seq` | 부팅 세션 안에서 취득 결과를 출력한 순번. 첫 값은 0이다. |
| `start_us`, `end_us` | 취득한 첫 표본·마지막 표본의 MCU 읽기 시작 시각. 단위는 µs이며 부팅 이후의 단조 시간축이다. |
| `gap_us` | 이전에 실제로 취득한 마지막 표본과 이번 첫 표본 사이 간격. 단위는 µs다. 이전 표본을 모르면 `null`이다. |
| `valid` | 센서 취득창 자체의 유효성. 기존 판정 가능 상태와 독립이다. |
| `reason` | 취득창 품질 사유. 기존 최상위 `reason`은 판정·운영 사유로 그대로 보존한다. |

표본 수는 기존 `samples` 필드로 확인한다. 0표본이면 시작·종료·공백은 `null`이고 이전 창 값을 재사용하지 않는다. 부분 취득은 실제 확보한 표본 범위만 남기며 유효창으로 처리하지 않는다. 정책 초기화가 발생해도 기록용 이전 취득 시각은 별도로 유지한다.

이 펌웨어의 시각은 **DATA_READY 확인 후 가속도 레지스터 읽기를 시작하는 MCU 시각**이다. 센서 내부의 변환 시각이나 읽기 완료 시각으로 해석하지 않는다. 분석에 쓰던 32비트 표본 시각과 기록용 64비트 시각은 같은 읽기 사건에 대응한다. 수집 PC의 수신 시각은 별도의 시계이며 두 시계를 직접 빼서 전송 지연을 계산하지 않는다.

`end_us - start_us`는 읽기 시작 경계 사이의 시간 범위다. 모든 순간의 물리 신호를 관측했다는 뜻이 아니며, `gap_us`에도 원래 표본 사이 간격이 포함된다. 이를 센서의 정확한 누락 시간이나 누락 개수로 바꾸어 부르지 않는다.

## 상태를 함께 읽는 예

- 수신 순번이 이어지고 창 품질이 유효해도, 양의 창간 공백은 별도로 표시한다.
- 센서 창은 유효하지만 FG 또는 정상 기준이 없으면 기존 판정은 보류될 수 있다.
- 센서 입력이 부분 취득·포화·시간 오류이면 이전 판정을 새 창의 결과로 복사하지 않는다.
- 오류나 정지 뒤 새 취득이 시작되면 실제 공백을 기록한다. 첫 창이나 구형 로그처럼 이전 시각을 모르면 미확인으로 남긴다.
- 세션 변경, 순번 누락·중복·역행은 수신 상태이며 센서 고장 유형으로 변환하지 않는다.

## 표시와 저장

`edge_module_c/pi/report_serial_logger.py`는 기존 로그를 계속 받을 수 있고 새 객체가 있으면 형식과 관계를 검증한다. 수신기가 계산한 순번 상태는 장치가 보낸 원본과 구분해 기록한다. 원래 `imbalance`, `imbalance_votes`, `ratio_1x`, 최상위 `reason`을 재계산하지 않는다.

수집기가 추가하는 `collector_report_transport`는 `source: "report_serial_logger"`, 순번 상태 `status`, 빠진 순번 수 `missing`을 담는다. 이는 수집 시점에 계산한 메타데이터다. 장치 입력에 같은 이름이 이미 있으면 덮어쓰지 않고 거절한다. 브라우저는 원래 세션·순번을 기준으로 표시 상태를 다시 계산한다.

`docs/index.html`의 기록 표는 수신 상태, 창 품질, 관측 범위와 창간 미관측 간격을 별도 항목으로 보여준다. 기존 표에는 시간축 그래프나 정상·경고 시간 합산 기능이 없으며 이번에도 이를 추가하지 않는다. 공백에 직전 상태를 채우거나 미관측 시간을 정상·고장 시간으로 더하지 않는다.

## 검증 범위

취득 메타데이터·직렬화, 구형 로그 호환, 잘못된 필드 거절, 순번과 세션 변경, 브라우저 표시를 호스트에서 검사한다. 기존 신호 검사와 Python/C 219회 정책 비교를 유지하고 ESP32 빌드를 별도로 확인한다. 추가 JSON의 전체 길이와 115200 baud에서의 이론 전송 시간을 확인한다.

이 검사와 빌드는 실제 센서 취득, UART 지연, 장기간 연속 운전 또는 고장 성능의 실측을 대신하지 않는다. 새 실행 파일의 RAM·Flash 사용량은 기존 보고서의 빌드 수치와 별도 기록한다.

기본 Arduino UART는 소프트웨어 TX 버퍼 없이 출력에서 대기할 수 있다. 추가 기록으로 인한 대기를 줄이기 위해 시리얼 시작 전에 2,048바이트 TX 버퍼를 설정한다. 이 메모리는 런타임 자원이며 기존 보고서의 정적 RAM 값에 포함된 것으로 설명하지 않는다. 버퍼가 가득 차거나 초기화되지 않으면 비동기 송신을 보장할 수 없고, 이 설정만으로 실제 시간 제약 충족을 검증한 것도 아니다. 115200 baud와 기존 100 ms 시간 단절 기준은 유지한다.

## 후속 확장: 실행 시간과 heap 관측

선택적 `runtime` 객체는 취득 품질과 별개인 운영 관측이다. 객체가 없는 기존 로그의 실행 시간·메모리는 미확인으로 남긴다. `runtime.v`는 현재 1이며 다음 필드를 사용한다.

| 필드 | 단위·경계 | 해석 제한 |
|---|---|---|
| `pre_emit_us` | µs. 현재 취득 시도의 시작부터 결과 출력 함수 진입까지 | 센서 취득 시간을 포함한다. 명령 처리와 일시정지 대기는 포함하지 않으며, 계산만의 소요시간이나 창간 공백이 아니다. |
| `previous_emit` | 첫 출력은 `null`, 이후 `{seq, call_us}` | `seq`가 가리키는 이전 결과 행의 소프트웨어 출력 호출 소요시간이다. 현재 행의 출력 시간으로 읽지 않는다. |
| `heap.free_bytes` | 바이트. `MALLOC_CAP_8BIT` allocator의 현재 여유 합계 | 전체 물리 RAM 또는 모든 메모리 종류의 여유와 같지 않다. |
| `heap.min_free_bytes` | 바이트. 같은 조건의 각 heap 영역별 최저 여유를 합한 값 | 영역별 최저가 발생한 시점이 다를 수 있으므로, 단일 시점의 전체 여유 최솟값으로 보장하지 않는다. |
| `heap.largest_free_bytes` | 바이트. 같은 조건에서 할당 가능한 가장 큰 연속 블록 | 현재 정보이며 미래의 할당 성공이나 장시간 운전을 보장하지 않는다. |

heap 값은 결과를 출력하기 전에 같은 `heap_caps_get_info()` 조회에서 얻는다. 센서 표본 읽기 내부에 heap 조회나 동적 할당을 추가하지 않는다. 출력 호출 시간은 `print_result()` 진입부터 마지막 `Serial.printf()` 반환 직후까지이며, 함수 내부 heap 조회·분기·포맷·쓰기·대기를 포함하지만 UART 선로 송신 완료나 PC 수신 시각이 아니다. 이전 출력 이후 정지했다면 다음 행에서 보여주는 값은 여전히 이전 `seq`의 호출 시간이다. 마지막 행 자체의 출력 호출 시간은 다음 행이 없으면 로그에 나타나지 않는다.

현재 행을 출력하는 데 걸린 시간은 출력이 끝나야 알 수 있으므로 다음 결과 행에 이전 순번과 함께 전달한다. 이를 측정하려고 송신 완료를 기다리는 `Serial.flush()`를 넣거나 기존 시간 단절 임계값을 완화하지 않는다. 순번 누락 시 `previous_emit.seq`의 행이 현재 파일에 없을 수 있으므로 파일의 바로 앞 행과 무조건 연결하지 않는다.

추가 JSON은 기존 baud·TX 버퍼·100 ms 정책의 제약 안에서 전체 직렬화 길이를 검사한다. 바이트 수로 계산한 이론 선로 점유 시간과 호스트 모의 출력 시간은 실제 보드의 전체 지연 측정이 아니다. 실제 병목은 장치에서 취득·분석·출력과 이 진단의 부하를 함께 측정한 뒤 판단한다.
